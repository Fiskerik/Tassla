# Dataåtkomst
`supabase.ts` skapar den delade klienten från de publika Expo-variablerna och kopplar in Expo Crypto före Supabase-init. Den rena `pkce-crypto.ts` adaptern och preflighten kräver säker slump och SHA-256; `expo-pkce-crypto.ts` är den enda nativebindningen. `secure-session-storage.ts` anpassar Expo SecureStore till Supabases nyckel/värde-kontrakt; `chunked-storage.ts` delar sessioner i UTF-8-bytebegränsade delar. `app-data.ts` läser ägarens hund/raser och anropar `create_dog` enligt SQL-kontraktet. `auth-callback.ts` validerar den fasta callbacken och Googles projekt-URL.

Flöde: Google OAuth eller magic link → `tassla://auth/callback` → PKCE-kodväxling → SecureStore-session → RLS-skyddad hund/contentläsning. `workspace-data.ts` läser vardagshändelser, publicerade träningsversioner/steg och hundens progression; skrivning av logg/träningssteg verifieras med återläsning när serversvar är osäkert. Hund skapas atomärt genom `create_dog`; klienten skriver aldrig medlemskap direkt. Databaskontraktet finns i `supabase/migrations/202610040001_foundation.sql`.

Kontroll: `pnpm check` kör TypeScript, lint och tester. `chunked-storage.ts`, `pkce-crypto.ts` och `workspace-data.ts` kan provas utan Expo-native UI runtime. Faktisk Google-retur, Supabase RLS och signerad iPhone kräver separat miljö-/enhetstest; ingen cache eller offlinekö finns. Använd endast den publika publishable keyn i Expo-konfigurationen, aldrig service-role-nyckel.
