# Träning

`PublishedTrainingScreen.tsx` is production Panel 6. The overview has **Rekommenderat**, **Alla övningar**, and **Mina** views, a maximum of two 4:3 recommendation cards, and a separate continuation card when confirmed progress has a next step. The views use published program versions, the active dog’s age/breed selection, and that dog’s `training_progress`.

## Data and behavior

`fetchTrainingWorkspace` returns only published versions and steps. Each program has `currentAgeBreedMatch`, which is true only if that exact version is selected by the current age/breed matcher. A started older version can remain resumable without being described as current-age-matched. The workspace route contract is unchanged.

`Rekommenderat` shows only age/breed-matched, unstarted programs with a real next step. Each entire card opens that exact step. `Visa alla` opens the full currently available program list. `Mina` contains programs with at least one confirmed completion in the displayed version and labels paused older versions separately. Unknown age removes age-based recommendations but keeps saved progress reachable.

The data contains no duration or subject taxonomy, so the UI does not fabricate time/category chips. Two distinct generated photos are decorative standard images without a visible badge after the owner’s 24 October cleanup request; image provenance remains in the manifest. The continuation card uses a third, distinct Corgi photo in a square 88×88 pt crop. Recommendation cards measure the whole copy block and share the largest natural height for the current width, font scale and content. The program name uses smaller regular metadata type than the bold exercise title. Cards keep full titles, and omit long step instructions from the overview; opening a card still reveals the full instruction. Home's current `Just nu` recommendation is text-only; it opens the same next exercise and does not show that photo.

A recommendation opens its exact exercise and exposes the journey start action in that same sheet. Program details place start/resume and confirmed journey totals before the step list. When a saved start, next, or back action returns before refreshed props arrive, the screen waits; it opens only the active step returned by the refreshed workspace. A paused journey has a direct resume action.

An exercise is saved with its published version ID and step ID through insert/readback. Legacy activity marking and unmarking stay available in a collapsed “Aktivitetsmarkeringar i programmet” section. Journey totals use logged sessions and unique owner-confirmed milestones; legacy activity counts do not stand in for journey progress. Only the first incomplete step can be marked. A confirmed step may be unmarked separately; the exact dog/version/step is deleted and re-read before Home updates. Failed or unknown writes do not appear as confirmed progress. The three views use shared accessible `Tabs`. In a program detail, reset is a 44 pt icon action that opens a named confirmation dialog bound to the exact current program; cancel does nothing, and confirmation calls the existing reset path once. The dialog does not promise an atomic reset. The interface describes the owner’s mark, not a verified skill.

The separate progression journey in a program detail is bound to one dog and one published version. Program cards show owner-confirmed milestones as a progress bar against the program's step count; logged sessions remain a separate total. A logged session uses three concise feedback choices and one save action. Journey details keep the unrelated legacy activity-mark section out of the pass and milestone flow, and clear any old success toast when logging begins. Only the latest saved `Gick som planerat` response offers the owner's separate, optional milestone confirmation; partial and early-ended sessions never offer it. The exercise modal shows a short decorative image, `Steg n/total`, a separate progress bar for confirmed milestones, and the required `AI-genererat innehåll` disclosure when applicable. Its navigation uses a full-width `Nästa` action and a separate `Föregående` action with direction icons; accessible names retain their full descriptions. Once confirmed, the step shows a compact `Klart` badge and adjacent `Ångra` action; the persistent status replaces a duplicate success toast. A failed confirmation stays visible beside the retryable confirmation action. Active journeys have no pause or maintenance controls; a previously paused journey can be resumed with `Fortsätt med nästa övning`, which resumes on the same exercise named in the card. Its current step can be opened as `Visa övning`, but pass logging remains unavailable until the journey is resumed. Older saved `maintenance` states are shown as `Pågår` and use the same controls as an active journey. Program sources use the shared compact, horizontally scrollable ContentSources links with short publisher labels, full page titles in accessible names and 44 pt targets. Unknown writes can be checked with the same operation ID. These counts remain separate from the older activity marks and Home's daily list.

Exercise details use the shared centered `BottomSheet`. Its actual exercise title and low face-focused banner stay outside the body ScrollView through the real headerContent slot. Instructions, progress and actions scroll without a visible indicator; close guards and the drag/swipe handles remain unchanged. A confirmed record_session receipt, including exact-operation retry, closes the exercise and shows a compact Passet sparat card on that program. Failed/unknown outcomes retain the modal and feedback. Only planned feedback plus ready current progression, matching active step, canConfirmStep and no pending mutation offers explicit Markera klart; a saved session never confirms a milestone automatically. Focused Home/Checklist/history detail routes are unchanged. Verify with tools/visual-check/verify-training-session-flow.py; synthetic browser results do not establish live persistence or native accessibility.

`TrainingScreen.tsx` and `training-model.ts` are local preview fixtures only. They are not production references. Review fixtures are memory-only; a real fetch error never falls back to examples. A real published-content read and RLS verification need a development Supabase environment.

## TRAINING-TIMELINE-01 — history and progress in the program view

The opened program uses a short decorative dog banner, a compact journey status row, and a vertical timeline. The active exercise is rendered only once in the timeline; earlier and future steps open as readable previews. Future steps are muted while keeping readable contrast and a 44 pt target. Journey history and upcoming previews have no write controls. Only the active step exposes journey actions.

Completion dates come only from `training_milestones.confirmed_at`. Older `training_progress.completed_at` remains a separate “Aktivitet markerad” date; on a future step it never replaces the primary “Kommande” state. Session `performed_at` stays a practice record and is not shown as the date a skill was completed. Missing or invalid timestamps are omitted. Date text uses the device timezone and includes a year when it differs from the current local year.

The current overview summarizes journey state and counts, then shows the step path without a second active-step card. Full instructions and pause guidance remain in the step detail. The banner reuses `training-recommendation-puppy-black-tan-park.jpg` with a vertical focus adjustment that keeps the generic dog's face and ears visible; it is decorative, not a photo of the owner's dog.

The synthetic RN Web flow is verified with `python -X utf8 tools/visual-check/verify-flow-training.py`. Evidence lives in `docs/design/evidence/training-timeline-01/`. This does not verify native iOS/Android rendering, VoiceOver/Dynamic Type, live Supabase/RLS, or TestFlight.

## Historical record

An earlier local redesign temporarily removed the three views. That decision is superseded by `FLOW-TRAINING-01` and current panel 6 in `vision_rev02.jpg`; it does not govern the active component.

Exercise reading uses `training-step-presentation.ts`: known title plus exact whitespace-normalized instruction matches get purpose-only goals and explicit verbatim numbered sentences. Unknown/revised content retains the original parser output; authored `## Mål` is supported. Structured recall keeps preparation, existing lists, adjustments and safety text. The touch exercise clarifies that its original “steg 1” means the previous contact exercise. No wording is removed and presentation never confirms a milestone. The low modal and journey banners use KnowledgeImage focal cropping to keep the whole face visible. Shared modals scroll naturally with vertical indicators hidden.
