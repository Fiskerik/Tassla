# Konto
`preview-policy.ts` är gemensam ingång för läget: exakt miljöflagga `true` plus utvecklingsbygge. `AuthProvider.tsx` äger produktens Supabase-session och växlar tokenförnyelse med appens förgrundsläge. `SignInScreen.tsx` skickar en begäran om tillfällig magic link. `AuthCallbackScreen.tsx` visar en lokal guard i förhandsvisning; i produktläge godtar den enbart `tassla://auth/callback` med exakt en `code`-parameter och byter den med PKCE. Inga token eller råa authfel visas eller loggas.

Dataflöde i produktläge: e-post → `signInWithOtp` → tillåten appcallback → `exchangeCodeForSession` → SecureStore via `src/data`. I lokalt testläge monteras inte AuthProvider. `Google` och OTP-kodinmatning ingår inte i detta flöde. Kör `pnpm check` för lokala kontroller. Begränsning: riktig mejlleverans och callback måste verifieras med signerad iPhone-app; ingen authbegäran skickas i lokala QA-kontroller. Kontoradering har ännu ingen klientåtgärd; SQL-triggern är inte ett raderings-API.
