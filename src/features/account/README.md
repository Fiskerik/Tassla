# Konto och inloggning
APP-04A: Inloggningsformuläret använder keyboard-aware scrollning, drag för att stänga tangentbordet och Klar på e-postfältet.

`AuthProvider.tsx` äger Supabase-sessionen med PKCE och ser till att inloggningsförsök inte körs samtidigt. Utloggning returnerar separat om lokal session är rensad och om serverns globala återkallning bekräftades. Om lokal rensning lyckas trots serverfel visas en sanningsenlig varning på signed-out-vyn; om lokal rensning inte kan bekräftas stannar användaren kvar och kan försöka igen. Ägarens lokala Tassla-påminnelser städas separat utan att blockera lokal utloggning; misslyckad städning visas som varning. `SignInScreen.tsx` erbjuder Google OAuth och den befintliga magic linken via e-post. Googles auth-URL måste använda HTTPS och samma värd som det konfigurerade Supabase-projektet, peka på `/auth/v1/authorize`, innehålla den fasta redirecten `tassla://auth/callback` och ha en SHA-256 PKCE-utmaning innan den öppnas. `expo-pkce-crypto.ts` kopplar installerade Expo Crypto-funktioner till WebCrypto-kontraktet som Supabase 2.117 behöver; auth nekas om kryptotestet misslyckas. Webbläsarförsöket håller auth-låset tills callbacken ger resultat eller användaren avbryter. Appen innehåller ingen Google-hemlighet.

`AuthCallbackScreen.tsx` godtar en kod på callback-routen och växlar den hos Supabase. En misslyckad kod skickas inte om och om igen, medan en senare ny kod kan hanteras. Callback-, provider- och nätverksfel ger ett generiskt återhämtningsmeddelande; koder, token och råa fel visas eller loggas aldrig. Callback-routen kontrollerar previewgrinden innan auth-context läses; lokal preview monterar inte `AuthProvider`.

Ägaren behöver konfigurera Supabase-projektets Auth URL-allowlist och Google-provideruppgifter i kontrollpanelen. Codemagic-arbetsflödet läser endast den publika Supabase-URL:en och publishable key från sin konfigurerade variabelgrupp och skickar inte automatiskt in ett TestFlight-bygge. Kör `pnpm check` för lokal typkontroll, lint och tester. Google-retur till appen, mejlleverans och faktisk sessionsägarskap behöver fortfarande testas i en signerad iOS-version; Expo Go kan inte verifiera den enhetsresan.
