# TRAINING-CONTINUE-PROGRESS-01 — visa framsteg i fortsättkortet

Status: granskad lokal leverans. Bas `14e50db` på `feature/complete-mvp-journeys`; root ensam writer. Eriks pågående MVP-mål och instruktion 2026-11-08 prioriterar synliga förbättringar. Pausad rutin-/sessionsdiff hålls orörd.

Problem: rekommenderade träningsvyns «Fortsätt där ni var» visar antal loggade pass och delmål som text men saknar framstegsstapel för publicerade träningsresor; detta påtalades i `docs/design/evidence/training-completion-01/VERIFICATION.md`. Användaren ska direkt kunna se hur många av programmets delmål som är bekräftade utan att blanda ihop pass med delmål.

Lösning: återanvänd `Progress` och den befintliga verifierade `trainingProgressionPresentation` för aktuell publicerad resa. Visa tydlig stapel med «x av y delmål bekräftade» och separat korrekt passantal. Resans noll/klartlägen är sanningsenliga; tomt program divideras inte med noll. Med pending/unknown/läsfel visas ingen föråldrad stapel eller uppfunnen bekräftelse. Fallback för äldre aktivitetsmarkeringar behålls och kallas inte delmål. Kortets hjälpmedelsetikett speglar samma kontrollerade antal, status och handling. Ingen ny lagring, API, råd, spårning eller dependency.

Skrivvägar: `src/features/training/PublishedTrainingScreen.tsx`, `tests/training-continue-progress.test.mjs`, `tools/visual-check/verify-training-continue-progress.py`, `tools/visual-check/verify-training-completion.py`, `tools/visual-check/app.tsx` endast vid nödvändig syntetisk fixture, `docs/design/evidence/training-continue-progress-01/`, denna task och eventuellt `docs/tasks/dev/rapport.md`/`docs/releases/HISTORY-2026.md`. Inga ändringar i pausade hem-/rutinpaths. Starta UI Critic BRIEF med faktisk basrender och Architect/Critic; därefter implementation, 0/delvis/alla/pending/unknown/läsfel/legacy och tillgänglighetsprov, syntetiska 375/430/375×667/140 % och UI REVIEW, oberoende QA/Reviewer, full `pnpm check`, public iOS JS-export och isolerad commit/push. Native VoiceOver/Dynamic Type och live Supabase/RLS är separata, inte PASS från RNWeb.

Architect/Critic PROCEED: värdet räknas på exakt samma journey/version; blockera vilseledande stapel om journey-ID inte matchar eller steg-ID är tomma/dubbla. Keya den animerade progressen till journey/programversion så en tidigare hunds eller resas stapel inte interpoleras in. Hjälpmedelsetikett anger båda antal och använder «Öppna» för pausad/osäker resa. UI Critic BRIEF VIEWED: låt stapeln fylla textkolumnen; bilden och ansiktet ska synas och kortet växa på höjden, utan textförminskning. Säkerställ smal/140 %-layout, 44 pt och tydligt åtskilda pass/delmål.

UI REVIEW: undvik dubblerad klartext när «3 av 3 delmål bekräftade» redan visas. Förtydliga motsvarande tidigare visuella regression i `tools/visual-check/verify-training-completion.py`, som läggs till skrivvägarna; andra vyers «Alla delmål bekräftade» behålls. Reviewer kräver faktisk stapelbredd/aria-värde, byte mellan två resor i samma vy och kontroll av pausat korts destination. Spara även pending-/unknown-bilder för visuell granskning.

RNWeb-fixturens delade `Progress` översätter inte native `accessibilityValue` till aria-valuenow; en synlig web-progressbar skulle därför kunna tolkas som obestämd. Reviewer kräver att den nya visuella stapeln döljs lokalt för hjälpmedel, medan hela kortets knappnamn innehåller exakt delmål och pass. Testa faktiskt synlig fyllnadsbredd samt att korrekt benämnd knapp inte ger en extra obestämd progressbar. Ingen ändring av den delade komponenten; native VoiceOver kvarstår NOT TESTABLE.
