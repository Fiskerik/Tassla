# APP-03 – riktig ägarapp, Google, Codemagic och visionsdesign

Plan v1, 2026-10-04. Erik vill nu integrera Codemagic och Google, sluta förlita sig på dummydata och efterlikna visionsbildens övre sex MVP-skärmar med ikoner/bilder. Codemagic är ännu inte konfigurerat enligt Erik. Mandatet omfattar att förbereda koden/byggvägen; externa konton/signering och verklig telefonresa kräver hans åtkomst. Ingen App Store-publicering eller extern pilot initieras.

## Leverans
Normal start/TestFlight ska visa Google-inloggning, riktig hundprofil och sex användarytor med ägarbaserad Supabase-data. Inga syntetiska hundar, loggar eller träningsregistreringar i produktflödet och ingen demo som reserv vid nätfel. Separat start:preview får finnas kvar som uttryckligt utvecklingsverktyg men behövs inte för den riktiga testresan.

Google: befintliga expo-linking och Supabase OAuth/PKCE, redirect tassla://auth/callback, skipBrowserRedirect true. Kontrollera URL mot samma Supabase-projekts HTTPS/auth-adress innan öppning. Inga Google-secret i appen. Samtidiga authförsök spärras; avbruten webbläsarresa/nätfel/ogiltig callback/nytt försök ger tydlig väg tillbaka. Callback ska tåla ny kod efter tidigare fel utan dubbla exchanges; rå kod/token/fel får inte loggas. Konton ägs av Supabase user-ID, ingen egen e-postbaserad merge. Magic link behålls som reserv. Fysisk Google-retur kräver signerad app, inte Expo Go.

Produktworkspace: aktiv användare äger state; konto-/hundbyte tömmer tidigare data och avbrutna gamla queries får inte skriva tillbaka. Logg läser dog_events för aktuell hund och sex vardagstyper, med begränsade sidor/mer-historik. UUID skapas kryptografiskt en gång per operation och behålls vid retry. Bekräftad molnsparning först efter serverresultat; okänt insert-resultat återläses via samma ID före nytt försök. Rättning/radering har timeout/fel och återläsning. Inga offlineköer eller optimistiska falska sparbesked.

Träning läser endast publicerade content_versions/training_steps och serverns training_progress. Faktiska versions-/steg-UUID används; insert/select/delete enligt befintliga grants, ingen update-upsert. Påbörjad publicerad version återupptas; indragen/saknad version visar pausat/saknat läge utan att flytta eller radera historik. Stegordning är klientbeteende, inte påstådd servergaranti. Fast innehållskontrakt utan migration: training-program-versionens body innehåller hela introduktion, målgrupp, stopp och begränsningar och visas FÖRE stegen; sources visas tillsammans med programmet. Inget program får automatiskt publiceras från previewkonstanter. Utan publicerade program visas tomt läge. Eventuellt separat förberett innehåll lämnas som granskningsutkast för Erik, inte automatiskt publicerat.

Hälsa och Tassla-pass förblir tydligt ofärdiga; ingen ny hälsoregistrering/PDF. Kunskap kan visa befintligt publicerat ålders-/rasrelevant urval, ingen påhittad artikeltext. Ingen ny datadelning, analytics, push eller externa meddelanden. Inga verkliga ägardata skickas till AI-teamet. Backendtabeller och RLS ändras inte i detta segment.

## Design och assets
vision_rev01.jpg, enbart övre delen: varm kräm, dämpat skogsgrönt, mindre apphuvud, tydliga kort, fotokort och konsekventa riktiga ikoner. Hem får hundöversikt med neutral hundikon (ingen stockhund som falskt profilfoto), verklig loggöversikt/nästa träning och genvägar. Logg får färgade ikonknappar och kompakt historik. Träning får dekorativt bildkort och tydliga steg. Kunskap/övriga ytor följer samma kort/navigation men utan fiktiva vårduppgifter/artiklar. Befintliga fyra huvudval och Mer ger tillgång till sex områden. Bilder är tillfälliga illustrationer, inte användaruppgifter. Minska rörelse, stor text, kontrast och touchmål ska fungera. Inga generiska teman eller emoji som ersättning för ikonfamilj.

Bildverktyget genererade två nya dekorativa beaglefoton i assets/images/dog-welcome.png och dog-resting.png. Built-in imagegen användes; inga API-nycklar behövdes. Prompterna gäller varm naturlig hundfotografi i skandinavisk hemmiljö, kräm/salviapalette, utan text/logotyper. Original sparas i Codex generated_images; dessa kopior används av appen.

## Paketförslag – kräver Eriks uttryckliga godkännande
expo-crypto ~57.0.3 för kryptografiska UUID som gör loggoperationer säkra att återläsa/försöka igen. @expo/vector-icons ^15.0.2 och expo-font ~57.0.4 för en konsekvent skalbar ikonfamilj; laddning/fel hanteras före användning. Versionerna kommer från installerade Expo 57:s bundledNativeModules.json. Ingen expo-web-browser, Google native SDK, EAS eller extra UI-framework behövs i detta förslag. Inga nya paket installeras innan Erik godkänt listan.

Vid olika ID stoppas skrivningarna tills kontot är utrett; ingen klientmerge via e-post. Dokumentera också testets ändamål, rättslig grund, kort information, lagring/radering och faktisk Supabase-region. Detta är ägarens interna test, inte en extern pilot.

Grind före TestFlight-uppladdning: Erik kontrollerar separat aktuella App Review-krav för integritetspolicy, kontoradering och likvärdigt inloggningsalternativ vid Google-login. APP-03 innebär inte att dessa är uppfyllda; uppladdningen väntar på separat beslut/arbete vid kvarstående frågor. TestFlight är villkorat redan i detta steg, inte bara offentlig release.

pnpm check, iOS-export utan .env, Expo versionskontroll och git diff --check. Kod/SQL-grants/importer och API:er verifieras mot installerade versioner. Lokal PASS innebär inte verifierad Codemagic-signering, Google-login eller RLS/runtime. Faktiska resultat dokumenteras separat; inga integrationsclaims utan körning. Ägarens Apple/Codemagicsteg kan blockera extern del men inte oberoende kod/visualarbete. Offentlig distribution kräver separat review av GDPR, butikens login-/raderingskrav och övriga releasekrav.
