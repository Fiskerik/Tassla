# ROUTINE-SAVED-NOT-SELECTED-01 — rutin sparad utan dagsval

Status planned · bas `bb667b8` · risk H · root ensam writer. MVP-COMPLETION-261031 steg4. Avgränsad förberedelse före dagklockans ändring; inga schema- eller nya dataändamål.

`createRoutineAndSelectForToday` skapar först en mall och försöker därefter lägga en engångsrutin på fångad dag. Om användaren byter scope efter att mallen sparats eller dagsvalet inte ens kan starta, returnerar vyn idag endast `saved`. Visa ett beständigt men avfärdbart besked att rutinen sparades men inte lades på ursprungsdagen och låt ägaren lägga till den själv. Aldrig skicka om skapandet eller flytta rutin automatiskt. För faktiskt avsänt dagsval behåll saved för ursprungsdagen och befintlig failed/unknown-recovery; unknown återanvänder samma operation/ID.

Ett separat in-memory ägarscoped notisfält får inte ersätta någon in-flight/unknown-mutation eller annan notis, ska behålla hund/dag och rensas vid signout/kontoradering. Endast samma giltiga konto/generation får publicera sena svar; efter hundbyte visas ursprungshundens namn och användaren får tydlig väg tillbaka utan att öppna fel hunds checklista. Ingen garanti över appens processavslut.

Plan v2 efter Security/Architect: även mallens ursprungliga `unknown` → uttrycklig retry → `saved` är en sparad engångsrutin där dagsvalet aldrig startades. Knyt återhämtningsmetadata för exakt operation (konto-/accountGeneration, ownerGeneration, hund, rutin, dag, zon) till pending; vid bekräftat saved efter samma-closure-retry lägg en notis, men anropa aldrig dagens val automatiskt. Unknown för faktiskt avsänt dagsval får inte behandlas så. Notiser ligger i separat oföränderlig FIFO, dedupliceras per submissionId/session och raderas exakt vid avfärdning; inga mutationer eller andra notiser trängs undan. Samma konto/generation och ownerGeneration kontrolleras även efter unmount; signout/kontoradering invaliderar butiken. Inga notiser om återkommande mall eller failed/unknown. Texten anger att appen inte lade till, inte att annan enhet saknar raden. QA kör verklig tvåstegsfunktion + workspace-/store-harness, inklusive template unknown → samma-ID-retry saved och A/B/A. Kritiker får omgranska v2 före implementation.
