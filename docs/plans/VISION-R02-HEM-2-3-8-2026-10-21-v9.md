## What this amendment changes

This amendment supersedes v8's View-segment/no-SVG implementation detail for Panel 3 and adds Dog Profile as a second entry to the same Panel 8 Insights view. It does not change the source-derived daily-progress model or the private owner-scoped Insights aggregate contract in v8.

The Panel 3 ring is one continuous `react-native-svg` stroke with rounded ends and a subtle green tone. It is smooth at partial progress, closes without a seam at 100%, and does not use a segmented View track. The Expo-compatible `react-native-svg` package is already in the application dependency graph; no new package is proposed. The visible Environment Training completion mark remains a larger, legible circular control with a check.

## Dog Profile entry and return behavior

- Add a clear `Insikter` action to the actual editable Hundprofil screen, `EditDogProfileScreen`, which is the component used when `ProductWorkspace` supplies `onDogUpdated`. Do not add it only to the read-only `DogProfileScreen` fallback.
- Place it as one secondary destination row/card immediately after the active dog selector and before the editable profile fields. Use the label `Insikter`, a restrained chart icon, and short purpose copy such as `Se registreringar över tid.` It must read as navigation, not another save action.
- The action opens the same Insights content as Logga → Översikt, with the same active dog, period selection, request scope, aggregate data, privacy copy, and refresh/error behavior. It is a second entry to the same view, not a second analytics feature.
- `ProductWorkspace` stores a scoped origin token: `log`, or `{ kind: 'profile', selectionKey, accountGeneration, dogId, profileReturnPage }`. `profileReturnPage` is the existing `more | training` destination captured when Hundprofil opens; opening Insights must not overwrite it.
- Entry from Logga → Översikt keeps the existing LogScreen mounted so its selected date and scroll state survive switching between `Idag` and `Översikt`. Entry from Hundprofil opens LogScreen on `Översikt` with `Logg` selected in the bottom navigation.
- For profile origin, show an explicit accessible `Tillbaka till Hundprofil` action on both the Översikt and Idag views. Back from Översikt returns to the same profile. Switching to Idag retains the profile origin and the same visible return action. This action clears the origin token and returns to Hundprofil; Hundprofil's own Back then uses the preserved `profileReturnPage`.
- Pressing the already selected `Logg` bottom tab while a profile-origin route is active clears the profile origin and opens `Idag`. Choosing any other main tab clears the token. Ordinary Logga entry has no profile return action.
- Clear the token and invalidate Insights data on owner/account-generation/dog-scope change. Never route back to a profile for a previous selection. If the route is still in Logga, it remains on the current Logga surface with current scope and no stale profile-return action.
- Do not discard profile edits to open Insights. The child screen computes one `canOpenInsights` gate from: unsaved dog-profile draft; unsaved kennel-attribution draft; profile busy, pending, or conflict; attribution busy; and any unresolved attribution write outcome (including unknown). It passes the enabled state/reason with the navigation callback so the workspace cannot bypass the gate.
- Keep the destination row in layout while disabled. Show persistent adjacent status text, not only an accessibility hint: profile draft → `Spara eller ändra tillbaka profiluppgifterna för att öppna Insikter.`; profile write pending/conflict → `Kontrollera profiländringen innan du öppnar Insikter.`; kennel draft/write unresolved → `Kontrollera kenneländringen innan du öppnar Insikter.`
- Unlock only after confirmed profile/attribution save, explicit accept-current/status reconciliation for profile writes, retry/readback resolution for unknown attribution writes, or the user manually changes every draft field back to the saved value. Do not refer to a reset/restore control that the form does not provide.
